# Проект асинхронной обработки команд (Async Bulk Processor)

## Описание проекта

Данный проект реализует утилиту для обработки команд, поступающих в виде потока данных. Он декомпозирован на две части:

1.  **Библиотека `libasync.so`**: ядро обработки команд, реализованное с использованием многопоточности (паттерн "Наблюдатель" и "Диспетчер задач").
2.  **Клиентское приложение `bulk`**: консольная утилита, которая использует библиотеку для чтения команд из стандартного ввода (`stdin`) и асинхронного логирования в консоль и файлы.

Проект поддерживает параллельную обработку нескольких независимых контекстов команд через C-интерфейс библиотеки (`connect`/`receive`/`disconnect`).

## Структура проекта

Проект организован в соответствии со стандартными практиками C++/CMake. Исходный код разделен на базовую (однопоточную) версию и многопоточные расширения:  
```
.
├── include/    # Заголовочные файлы
│ ├── async/    # Публичный API библиотеки (async.h)
│ ├── base/     # Заголовочные файлы базовой (однопоточной) версии
│ └── mt/       # Заголовочные файлы многопоточных расширений
├── src/        # Файлы реализации (.cpp)
│ ├── async/    # Реализация публичного API
│ ├── base/     # Реализация базовой (однопоточной) версии
│ └── mt/       # Реализация многопоточных расширений
├── unit_tests/ # Юнит-тесты
│ ├── boost/    # Тесты с использованием Boost.Test
│ └── gtest/    # Тесты с использованием Google Test
└── googletest/ # Субмодуль Google Test
```

## Сборка проекта с использованием CMake

Для сборки проекта вам понадобится компилятор C++17 (например, GCC 9+ или Clang 9+), CMake версии 3.12 или выше и библиотеки Boost (если включены тесты Boost). 

### 1. Клонирование репозитория (включая субмодули)

`git clone https://github.com/r0973/otus-cpp.git`  
`cd otus-cpp`  
`git checkout feature/asyn_bulk_parser`

### 2. Создание каталога сборки

`mkdir build`  
`cd build`  

### 3. Конфигурация проекта

`cmake ..`  

#### Опционально: Вы можете отключить сборку тестов Google Test или Boost, добавив параметры при конфигурации:

`cmake .. -DWITH_GOOGLE_TEST=OFF -DWITH_BOOST_TEST=OFF`  

### 4. Сборка проекта
`cmake --build .`  

### 5. Установка проекта (Копирование артефактов в build/install/)
Этот шаг копирует скомпилированные файлы (`bulk`, `libasync.so`, `run_test.sh`) в целевой каталог `build/install/bin` и `build/install/lib`.

`cmake --install .`  

### 6. Запуск и тестирование
После установки все необходимые файлы находятся в каталоге `build/install/`.

#### 6.1. Запуск вручную
Вы можете запустить клиентское приложение `bulk` вручную из каталога `build/install/bin`. Не забудьте установить переменную окружения `LD_LIBRARY_PATH`, чтобы система знала, где искать `libasync.so`:

`cd build/install/bin/`  
`export LD_LIBRARY_PATH=../lib:$LD_LIBRARY_PATH`  
`./bulk 3`

#### 6.2. Использование автоматического скрипта тестирования
Проект генерирует скрипт `run_test.sh` в каталоге установки. Этот скрипт запускает два независимых клиента параллельно и автоматически обрабатывает `LD_LIBRARY_PATH`.
Запустите его из каталога `build/install/bin/`:

`cd build/install/bin/`  
`./run_test.sh`  

Вывод скрипта покажет консольные логи и содержимое сгенерированных файлов (`bulk*.log`), подтверждая работу асинхронной обработки.

#### 6.3. Запуск юнит-тестов
Если вы собирали тесты, вы можете запустить их из каталога сборки:

`cd build/`  

#### 6.4. Запуск тестов через ctest
`ctest`
